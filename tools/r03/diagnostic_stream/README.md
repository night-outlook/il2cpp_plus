# General diagnostic serializer: shared legacy and bounded sink

The actual AssemblyShadowDiagnostics::Serialize and SerializeTo use one schema/escaping body. Serialize preserves its legacy string API. SerializeTo accepts a caller-owned synchronous bounded sink, reports successful accepted bytes and fails closed on overflow, sink failure, re-entry, reuse, invalid inputs or unsupported non-classic C++ locale. A failed prefix is never a complete semantic result. Snapshot layouts and public StateName/UseKindName/Quote remain unchanged. Inputs must be immutable, disjoint, single-owner and fully captured before formatting; no VM/transaction lock may be held across an external sink.

This is formatting integration, NOT bounded live VM acquisition. Existing GetDiagnosticsJson still constructs a heap-backed snapshot. GetExecutionDiagnosticsJson now uses a shared typed execution-field formatter for its legacy string result; VM acquisition, metadata map allocation, runtime counters, and the unbounded output buffer remain unchanged. The new API is not wired to the Player, managed API, durable files or V2 semantic verifier. No engine scheduling/lifecycle behavior changes.

Tests compile the frozen original serializer, current legacy API and actual current SerializeTo; all fields, old string tokens/order, snapshot declarations and control-byte escaping must match. New code streams a synthetic 4096-class general diagnostic into the real bounded native Capture/Encoder and compares the wire byte-for-byte with the reference. Slot15 remains the complete output of the **immutable historical N** function under synthetic VM mocks, not a new streaming execution producer. Before either general test profile, the runner additionally compiles both exact historical and current production execution function bodies using the same unchanged N fixture and verifies full JSON bytes (the original 331078-byte large case, empty classes, and deterministic IL2CPP_DEBUG/class-field state case), in both strict and ASan/UBSan builds. Current and frozen source identities are independently pinned; neither historical extract nor its old test helper is rewritten. The current producer must differ from the historical *source* but match its *bytes* for the same inputs. Test results include an explicit six-case parity receipt, 24 compile/process records, and a fail-closed RESULT/MANIFEST even when a source gate fails before general cases start.

Test-only scalar/array/aligned operator-new accounting runs after all input/output buffers are prepared.
