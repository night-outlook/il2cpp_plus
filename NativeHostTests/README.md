# Native-only host tests

## R03 B2 inactive original V1 field15 observational byte-parity probe (2026-11-12 UTC)

**Original GetExecutionDiagnosticsJson remains unchanged.** New production-source, *inactive* `libil2cpp/vm/AssemblyShadowExecutionV1ByteParitySource.inl` introduces `AssemblyShadow::TryProbeBoundedExecutionV1ByteParity`. A caller preallocates physical membership, owned rows, bounded record and a single-use pure `assembly_shadow_execution_v1_parity::Probe`, and owns an exclusive `std::string` for the original V1 getter's bytes. The probe acquires an **outer initial-session metadata Reader**, invokes the existing `TryGetExecutionDiagnosticsWithMetadataAdmission` around the **real original V1 getter** (which may allocate), then runs the separate restricted physical-class bounded producer and checks exact byte-for-byte equality of their immutable JSON. There is **no Unity Player caller or transport wiring**.

`libil2cpp/vm/AssemblyShadowExecutionV1ByteParity.h` is pure, C++11, noncopyable, fixed-size, no heap storage and no retained metadata/input pointers; records exact original/bounded lengths and first differing byte offset, with a 3,932,160-byte per-input cap. It consumes exactly one comparison; a mismatch, oversized/unavailable original V1, failed native bounded source or reuse **revokes** the bounded record, clears the source receipt/legacy string, and cannot yield positive product status. A successful compare only yields `exactBytesObserved=true` and `twoIndependentObservationsOnly=true`: `coherentVmEpochProven=false`, `fullCanonicalTypeKeysProven=false`, `terminalSafeFinalExecutionDiagnostics=false`, `nativeV2TransportImplemented=false`, `runtimeAcceptance=false`, `R03Accepted=false`, `H2Passed=false`. A cross-source mismatch can result from real temporal cctor/counter/metadata differences, not necessarily a TypeKey formatter defect. This API is healthy-time only, not terminal-safe.

**Evidence scope:**
- `NativeHostTests/AssemblyShadowExecutionV1ByteParityHost.cpp` compiles the genuine pure comparer and exercises ten exact/equal/mismatch/reuse/budget/invalid-input cases; [CI run 43146317881](https://github.com/night-outlook/il2cpp_plus/actions/runs/43146317881) **4/4 macOS/Ubuntu C++11/17 jobs PASS**, Release/Debug strict/ASan-UBSan (16 executions × 42 assertions).
- `NativeHostTests/AssemblyShadowBoundedDefinitionExecutionSourceMock.cpp` also compiles the **actual new parity-source .inl** and the actual restricted native TypeDef .inl. Its standalone **fake reference V1 getter reuses the same bounded source** to test only equal/different/unavailable/reuse adapter mechanics; it is explicitly **not** the real original V1 implementation. [CI run 43146273936](https://github.com/night-outlook/il2cpp_plus/actions/runs/43146273936) **4/4 PASS** in the original 16-process Mac/Linux C++11/17 Release/Debug strict/sanitized matrix; 67 original source-mock scenarios, three parity-adapter cases and 1,258 assertions/process.
- Actual original V1 invocation is source-wired in production .inl, but no full official Unity `AssemblyShadow.cpp` translation-unit compile or Player execution, original V1 nonempty class bytes, or real metadata epoch comparison has happened. A real equality *cannot* be inferred from the synthetic VM host, and equality across two real reads still does not prove a single coherent VM epoch.

The primitive null-safe default Peek, original Unicode case-fold and class-owner source remain unchanged and retain their own reviewed evidence. The new probe does **not** implement complete field15, full terminal-safe field14, native V2 artifact/envelope/receipt, B3 whole-VM epoch, or Local execution authority. `WEB_TO_LOCAL.md` stays **CLOSED / NO EXECUTION**. Keep host drivers/global new/delete overrides under NativeHostTests; never install/link them into GameAssembly.



## R03 B2 pre-existing primitive defaults source (2026-11-12 UTC)

The *inactive* VM TypeKey source now supports the original FormatType fallback for supported primitive type codes **only when their original preinitialized il2cpp_defaults class can be independently proven to own a registered physical AOT metadata TypeDef**. The inactive source uses the NEW assert-free `assembly_shadow_existing_primitive_defaults::Peek`, whose 19 case-to-field mappings are mechanically compared in the exact source gate against the ORIGINAL `Class.cpp::FromIl2CppTypeEnum` switch. The original API asserts a nonnull default in Debug; using it directly would abort when a default is unavailable. The new view returns null without calling the asserted API, Class::FromIl2CppType, GetPtrClass, class initialization or metadata cache construction. It is **not** a general-purpose fallback for arbitrary type tags.

For each primitive argument, the returned class must be nonnull, a nonconstructed/nonarray class with a nonnull physical image and metadata handle, a zero-arity root TypeDef, and be owner-verified against the already admitted original physical AOT assembly registry *before dereferencing the handle*. The physical TypeDef's namespace/name must equal the original class declaration names; otherwise the source fails closed. It retains the existing g_MetadataLock, initial metadata Reader, membership revision/R02 counter/B1 first-error observation fences and one-owner frozen-row staging. New `usedExistingPrimitiveDefault` and `admittedPrimitiveArguments` receipt fields are scrubbed on any failure. Unsupported VAR/MVAR remain rejected, consistent with the original `FormatMetadataOnly` image-map branch. Other primitive codes without a proven existing class or registered TypeDef are rejected, not replaced with guessed system type names.

The exact native `.inl` source mock tests a preinitialized Int32-style default class in a separate unobserved AOT image, a qualified primitive and negative missing default, unregistered/ambiguous/wrong image or handle, unknown tag, generic arity, class-name and declaration-ancestry mismatches. These are **synthetic model classes** and not an official Unity metadata ABI or complete V1 field15 parity test. Real Unity standard primitive classes may not all satisfy physical handle constraints; no unrestricted primitive coverage is asserted. The original V1 getters and B1 producer are unchanged. The host compiles the ACTUAL new no-assert primitive Peek header against a fake `il2cpp_defaults` layout, testing all 19 supported type-code fields with both null and existing pointers (20 total positive/negative table scenarios). The exact-source audit pins the **actual original** Class.cpp/Class.h implementation and checks mapping-by-mapping correspondence; the real Class.cpp is NOT compiled in this host. Source tests prohibit class creation/cache paths. No global allocation-guard host driver enters production `libil2cpp`.

This is a source-only checkpoint, not terminal-safe full field14/15, native V2 transport, VM-wide epoch, or Local execution authority; `WEB_TO_LOCAL.md` remains CLOSED / NO EXECUTION. The previously consumed B1 oneuse-12 focused Unity Player PASS is not acceptance evidence for this new source.

## B2 original registered-AOT TypeDef owner source (2026-11-11 UTC)

The inactive `TryCaptureBoundedDefinitionExecutionLive` now obtains a distinct bounded image inventory from the **raw registered physical `s_Assemblies` table** in `Assembly.cpp`, not from the logical `Assembly::GetAllAssemblies()` snapshot or solely from initialized class enumeration. `Assembly::TryVisitRegisteredAotImages` runs under `s_assemblyLock`, using the real pure `AssemblyShadowRegisteredAotImageScan.h`; its caller holds `g_MetadataLock` and the initial-session metadata Reader. Nonzero physical AOT assemblies with **zero TypeDefs** are valid and skipped (they cannot own a metadata TypeDef); interpreter and invalid-token entries are excluded. A malformed assembly/image backreference rejects the whole source.

The class producer also keeps its two observed-class passes and original registry/witness proof. It snapshots the raw registered AOT image set before and after the class metadata pass (up to 1,024 distinct images), compares bounded ordered image identities, and rejects missing/ambiguous/unregistered owners. Thus a concrete `GENERICINST` argument from a registered AOT image **without any observed class** is eligible under the supported canonical TypeDef subset, but not an array/open variable/nested constructed generic/qualified shape. The unchanged 64-observed-image, 8,192-TypeDefs-per-image, 65,536-owner-lookup, 16-argument and 4,096-byte key limits still apply.

`AssemblyShadowBoundedDefinitionExecutionSourceMock.cpp` uses the **actual pure AOT scan header** with mock assembly structures, compiles the actual inactive VM source `.inl`, and tests both registered-unobserved positive source and malformed/changed/overflow registry cases. The two lock-scoped snapshots are only observations, not a coherent VM epoch/metadata teardown proof. Neither `Assembly.cpp` nor linked GameAssembly has been officially compiled with Unity in this source-only cycle. Host-only global allocator overrides MUST remain outside production libil2cpp. No native V2 writer, real Player or Local Validation is authorized by the mock suite.
